# Coding agents

Coding agents use adder through its [MCP server](#mcp), which offers adder's commands as tools, or the way scripts do: every command that runs prints one JSON object with `--format json`, problems have stable codes, and each generator describes its inputs with a JSON Schema. An agent that follows the steps below adds code the way the repository's people do, and never edits a generated file by hand.

## The loop

1. **Find the generators:** `adder list --format json` lists every generator, with its description.
2. **Read one:** `adder describe <generator> --format json` gives its inputs, the values its scans allow now, and `inputSchema`, a JSON Schema for the inputs.
3. **Preview:** `adder new <generator> --inputs - --dry-run --format json`, with the inputs as a JSON object on standard input, lists the files it would create and update, or the problems with the inputs, without writing anything.
4. **Run:** the same command without `--dry-run` creates the files, updates the derived ones, and returns the generator's message, such as what to write next.
5. **Keep derived files current:** after changing code by hand, `adder derive` updates the files that depend on it, and `adder check` exits 3 when any is out of date.
6. **Change generated code at its source:** a file whose header says `Code generated by adder ... DO NOT EDIT.` is rewritten on the next derive. `adder explain <file> --format json` names the template and output it comes from, which is what to change instead.

Warnings, such as the use of something deprecated, come in `warnings` beside `problems`, and say what to use instead.

## An AGENTS.md section

Copy this into a repository's `AGENTS.md`, or the file its agents read, and adjust the generator names:

```markdown
## Code generation with adder

This repository generates code with adder (`go tool adder`). Its generators and derived files are declared in
`adder.yaml`.

- To add a component, use a generator instead of writing the files by hand. List them with
  `go tool adder list --format json`, read one with `go tool adder describe <generator> --format json`, and preview with
  `go tool adder new <generator> --inputs - --dry-run --format json` before running it without `--dry-run`.
- Never edit a file marked `Code generated by adder ... DO NOT EDIT.`. Run `go tool adder explain <file>` to find
  its template, and change that instead.
- After changing code that a derived file depends on, run `go tool adder derive`, and commit the result with the
  change. `go tool adder check` must pass before committing.
- Fix every warning adder reports about something deprecated, as it says.
```

## MCP

`adder mcp` serves adder's commands as tools over the [Model Context Protocol](https://modelcontextprotocol.io), so an agent calls them directly rather than in a shell, and the client asks before each call as it does for any tool. Start it as `go tool adder mcp`, which runs the adder `go.mod` pins, with the repository's own packs. With Claude Code:

```sh
claude mcp add adder -- go tool adder mcp
```

Other clients take the same command in their configuration, such as `.mcp.json` at the repository root:

```json
{
  "mcpServers": {
    "adder": {"command": "go", "args": ["tool", "adder", "mcp"]}
  }
}
```

| Tool | Arguments | Does |
| --- | --- | --- |
| `list` | | List the generators and derived outputs. |
| `describe` | `generator` | Describe a generator, with a JSON Schema for its inputs. |
| `explain` | `path`, from the repository root | Name the output and template that produce a file. |
| `check` | `diff` | Report derived outputs that are out of date. |
| `test` | `generators` | Run generators' tests against their golden files. |
| `preview` | `generator`, `inputs`, `diff` | Show what a generator would create and change, writing nothing. |
| `derive` | | Update every derived output. Only with `--write`. |
| `new-<generator>` | the generator's inputs | Create a generator's files. One tool per generator, only with `--write`. |

- Without `--write`, the server only reads. Add it, as `go tool adder mcp --write`, to let the agent create files and update derived outputs.
- Each tool returns what its command prints with `--format json`, and is an error when that has problems.
- `adder.yaml` is read for every call, so changes apply without restarting the server, and the generator tools follow it.
- The server gives the client the guidance above, so an agent knows not to edit generated files without being told.
- It serves one configuration: the one found from where it starts, or `--root`. In a monorepo, add one server per configuration, each with `--root`.
